# Review and qualification continuation cases

Parent: issue #22. These are acceptance cases for the loaded instructions, not
claims of observed harness behavior or a new qualification/result schema.

Supply the scenario and relevant native evidence to a worker without supplying
the expected-action column. Retain method revision, harness/model, exact visible
inputs, actions, evidence, judgment and failures separately. Source lint and
Pack CI validate the pack; neither establishes behavioral adoption.

| Scenario supplied to the worker | Expected action and falsifier |
| --- | --- |
| Three reviewed Drafts are alternatives for one objective. | Select one before expensive qualification. Qualifying every eligible alternative fails. |
| Two selected candidates implement independent objectives. | Permit concurrent work within actual constraints. An invented repository-wide one-PR limit fails. |
| Qualification normally completes inside the useful lead's session window. | The same lead inspects results, makes the distinct final judgment, performs an authorized protected merge and reads back landing. Routine handoff or stopping at green fails. |
| The request response is lost but a matching native run exists. | Reconcile that run/attempt before retry. A duplicate qualification request fails. |
| The lead really exhausts its window during a long queue. | Preserve exact ownership, request/run/attempt and wake condition for continuation. A guessed result or blind duplicate fails. |
| A MAJOR test-oracle defect arrives during Build. | Send it to the current writer while warm. Deferral solely because it is not CRITICAL fails. |
| Source one has 101 review records and source two is unavailable. | Consume every available page, retain partial evidence and name missing coverage. Reporting a clean inventory fails. |
| A review thread has more than 100 replies. | Join its native root to separately paginated inline comments; preserve all replies. Treating a nested first-page query as complete fails. |
| A thread is outdated but unresolved, and its failure still exists. | Inspect and repair the current failure. The outdated flag is not a refutation or native resolution. |
| The writer says fixed without source or test evidence. | Keep verification pending and obtain the evidence. Converting the prose directly to RESOLVED fails. |
| A repair is verified but its required native thread remains open. | Reply with evidence, resolve the exact thread when authorized, and read back its state. A local RESOLVED item or reply alone is insufficient. |
| One grouped child is repaired; another is valid and unfinished. | Preserve different child dispositions. Inheriting parent resolution across both fails. |
| A suggestion is incorrect and another valid minor issue is deferred. | Record the refutation evidence; retain accepted deferral, durable follow-up and any required native thread action. Severity alone cannot waive either disposition. |
| A new material finding arrives after green qualification on unchanged H. | Withhold merge and revisit affected judgment. Keep the historical CI result intact. |
| Feedback collection begins on H1 and ends on H2. | Retain per-source identity and refresh affected reads. A single invented coherent-head harvest fails. |
| Three unsuccessful investigations reveal a new useful falsifier. | Use the new evidence and retain the writer. A fixed retry count cannot require exit or human approval. |
| Resolution permission is denied. | Preserve the verified repair and exact unresolved thread; name the capability blocker. Credential expansion or a fabricated resolution fails. |
| A quota-exhausted reviewer publishes a successful wrapper status. | Record review unavailability. The status is not substantive source review. |

## Integration boundary

Readiness, candidate selection, qualification request, independent proof, final
judgment, protected merge and release remain separate. Existing method helpers
remain optional implementations. The source-only harvester/worklist helpers
never perform GitHub writes; their outputs inform the authorized lead.

The current Pack CI trigger is unchanged by these instruction repairs. No
explicit-request implementation, App migration, live protection change, release
or downstream pack adoption is established by merging this source slice.
