# Flow 5: Independent qualification

Buy the remaining required assurance after warm development and substantive
review. This flow requests and reconciles proof; it does not merge, tag or
release. A qualification pass is an input to Flow 6's separate judgment.

## Admission before allocation

Inspect the current issue/claim, candidate and actual base, reviewed findings,
original local evidence and the repository's implemented qualification adapter.
Resolve missing or stale source review first. Do not require the qualification
result that this request is intended to produce as a prerequisite to request it.

Select the candidate actually intended to land for this objective before
allocating expensive qualification. Alternative Drafts may be implemented and
reviewed cheaply; technical eligibility is not a request to qualify each one.
A later switch of candidate needs its own current request and applicable proof,
not its sibling's green status. Selection is per objective, not a repository-wide
one-PR limit: independent objectives may qualify concurrently within real
capacity and integration constraints. Use existing issue/PR ownership records,
not another selection database.

Select applicable mandatory obligations and justified risk-directed proof through
the existing product planner. Each obligation must execute, reuse admissible
original evidence, be demonstrably inapplicable, or remain blocked/not proven.
An available-tool catalogue is not an instruction to run every instrument.
Unknown impact widens proof or blocks; a cache hit is not a test result.

Verify actual tested source, command, environment, executed subjects, completion,
producer/custody and present applicability. A candidate-head test is not an
integration-result test. Dirty/staged inputs need actual identity, not HEAD
alone. Preserve useful earlier proof without relabeling it as a new execution.

Use the actual repository request operation with the current candidate,
review/evidence, selected obligations and request identity. A request for H1
cannot be inherited by an H2 push or retained label. Ordinary open/update/reopen,
Draft/Ready and unrelated labels do not request qualification in the target.

If the installed route is still legacy, name its actual behavior and use only
the migration owner's approved qualification path. Do not invent a command,
disable a check or use candidate-authored success data as authority.

## Execute and reconcile

Read back the accepted native request/run/attempt. An acknowledgment is not a
complete result. On duplicate delivery or lost response, observe the existing
operation before deciding whether another attempt is justified. Preserve useful
in-flight work and original evidence; do not automatically cancel it on a push.

The same useful owning lead normally carries the request through the ordinary
CI wait, complete result inspection, Flow 6's separate final judgment, authorized
protected merge and landed readback. Different decisions do not require different
agents or a routine human approval. Do not stop at green or hand off merely
because a named flow ended.

Use supported wait/event handling or bounded checks without tight polling;
useful independent work may proceed while retaining candidate ownership and warm
context. An actual interruption, unusually long queue or exhausted session gets
an exact request/run/attempt checkpoint and next wake condition. That recovery
path is not the default for a normal in-window wait. A child finishing does not
mean the selected proof portfolio finished.

Normal complete active qualification targets <=20 minutes including required
setup, children and finalization. Measure request/queue latency separately and
retain all failed/retried attempts and shifted local costs. Never meet the timer
by hiding obligations, accepting empty execution or weakening the oracle.

The trusted result consumer must distinguish product failure, required missing
proof, optional unavailability, inapplicability, cancellation, instrument failure
and publication failure. A skipped job or successful admission wrapper is not
product qualification. Required success follows complete admitted evidence on
the actual subject and confirmed result publication where that is required.

## Repair and exit

An execution failure returns its original evidence to the warm writer or owning
instrument repair. Do not edit the frozen candidate inside the independent
qualification transaction. A new source subject requires reassessing affected
review/proof and explicitly requesting the justified successor. No fixed retry
count grants a pass or prohibits useful investigation.

Preserve existing gate artifacts as observations with their original schema and
meaning. Do not emit a legacy MERGE verdict merely because tests passed. A legacy
combined receipt cannot substitute for the separate current final decision.

A complete applicable result proceeds to `/flow-6-deploy`. A new material review
finding routes back to `/flow-4-review`, even on unchanged source; historical
passing tests remain true. Missing capability/evidence receives a precise held
result and next action. No merge, auto-merge, queue, tag, release or protection
change is an effect of this flow.
